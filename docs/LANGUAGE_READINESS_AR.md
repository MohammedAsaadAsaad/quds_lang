# خطة اكتمال لغة قدس وأدواتها

هذا الملف نقطة استلام للعميل التالي. مواصفة اللغة **1.2** هي المرجع، وإصدار
حزمة المترجم مستقل عنها. لا تغيّر الصياغة المعتمدة لتجاوز مشكلة تنفيذية.
الهدف توافق موثّق مع Dart وتجربة تطوير متكاملة، وليس إضافة صياغة خاصة بفلاتر
إلى قلب اللغة. الأقسام الأقدم تحت هذه الدفعة سجل تاريخي. الحالة الحالية هي
القسم الأول أدناه؛ الأقسام التالية تحفظ نتائج الدفعات السابقة.

## الدفعة الحالية: أحمال الطرق وافتراضيات الأب الخاصة — مكتملة ضمن نطاقها

الأساس `662adb3`. ABI أصبح `provider-defaults-v7`.

طرق الصنف ذات التواقيع المختلفة تُصدَر `name$1` و`name$2` بترتيب المصدر.
النداء يختار مرشحًا واحدًا في وقت الترجمة: مرشح بلا variadic يغلب مرشحًا
variadic، ومرشحان منطبقان بلا variadic يعطيان `E310` حتى لو كان أحدهما أكثر
تخصيصًا. قيمة الطريقة بلا توقيع متوقع واحد تعطي `E311`. التنفيذ الذي يطابق
توقيع الأب أو الواجهة ينسخ اسم Dart نفسه. الاختبار يطبع `a` و`n2` و`b` و`n3`
و`cc` و`n2`.

طفل بلا منشئ، وأبوه في مكتبة أخرى بافتراض غير حرفي، يستدعي
`$QudsCtorSlots` على الأب. الناتج `7` ثم `ok` ثم `4`، وملف الطفل لا يحتوي
`_seed` ولا `_q0()`. افتراض حرفي ثابت، و`super.value` بافتراض، وصنف عام
بافتراض `int` تُنفَّذ وتطبع `4` و`8` و`1` و`5` و`2`.

`dart analyze lib bin test` بلا ملاحظات. `dart test` أعطى 730 نجاحًا
وفشلًا واحدًا في 5 دقائق و56 ثانية: `quds create flutter writes the app in quds`
لأن حزمة Flutter المحلية تسبق نوع الواجهة (`extends _qNative….StatelessWidget`).
هذا الفشل سابق لهذه الدفعة.

ما زال مفتوحًا: المجموعات الاختيارية المختلطة، وdefault مع variadic في قيمة
واحدة، وقيم دوال Dart التي لا تحمل بيانات الحذف، وافتراض محسوب نوعه معامل
نوع للصنف، وشهادة 91 قاعدة، وF5 الأصلي وpub.dev. لا تُعلَّم أي قاعدة `complete`.

## الدفعة السابقة: فراغات المعاملات وافتراضيات الباني — مكتملة ضمن نطاقها

الأساس `61dc336`. ABI أصبح `provider-defaults-v6`.

نداء optional positional المستورد يستطيع تخطي خانة سابقة مع تمرير خانة لاحقة
عبر جسر `$QudsGap` / `$QudsMethodGap` بالشكل `(List<Object?>, List<bool>)`.
القيمة المخزنة تبقى tear-off الموضعي نفسه حتى تبقى المساواة، ويُربط به Expando
يشير إلى الحزمة دون نسخ defaults الخاصة إلى المستدعي. النداء المباشر في المكتبة
نفسها ما زال يقيّم الافتراضي محليًا. قيمة دالة Dart غير المعروفة تبقى E910.

الباني المستورد ذو الافتراضي غير الحرفي يستدعي `$QudsCtor` الساكن على الصنف،
فيُقيَّم `_seed()` داخل المزود مرة واحدة عند الحذف فقط. الحرفي يبقى منسوخًا.
التركيب يغطي منشئًا أبويًا توليديًا واحدًا بلا اسم؛ المنشئ المسمى فقط أو
variadic أو تصادم اسم الحقل يبقى E910. افتراضي أبٍ خاص مستورد لا يمر بعد عبر
`$QudsCtor` عند التركيب.

lambda تقبل `required` والأقواس والافتراضي، وتُرفض المجموعات المختلطة بـE910.
`name: Type = expr` لم يعد يُمرَّر موضعيًا. المعامل الأول في دوال مثل
`normalCdf(x)` يبقى dual، أما `center` و`sigma` فأصبح تمريرهما بالاسم في
SDK والاختبارات. required named يُنفَّذ كـoptional named
باسم مطابق وdefault. حارس readonly لطريقة ذات معاملات يلف نتيجة الاستدعاء داخل
المحوّل بدل رفض القيمة.

ما زال مفتوحًا: overloads طرق الصنف `name$1`/`name$2`، وdefault مع variadic في
قيمة واحدة، والمجموعات الاختيارية المختلطة، وقيم الدوال الأجنبية، وشهادة 91
قاعدة، وF5 الأصلي وpub.dev. لا تُعلَّم أي قاعدة `complete`.

## الدفعة السابقة: metadata لـrequired وoptional positional — مكتملة ضمن نطاقها

الأساس `d4851c3`. أضيف ParameterKind إلى AST، مع حفظ kind في parser
ونسخ المعاملات المستوردة والمتخصصة وconstructor signatures. الموضع يتجاوز
required named slots، وتحافظ مراجع الدوال على required labels وbracket groups.
implicit null يُقبل للنوع nullable ويُرفض للنوع غير nullable. اختيار overload
يشمل الأسماء المسماة، والتواقيع المعروضة ترتب positional قبل named دون تغيير
ترتيب تقييم الوسائط المكتوبة. named-required قد يلي named default.

جسور الدوال وطرق الكلاسات والواجهات العامة وreadonly تدعم الأشكال القابلة
للتمثيل. أُصلح ضياع synthetic constructor signatures وكذلك التخصص العام
ذي prefix. القيم الافتراضية literal للبواني مختبرة؛ non-literal imports تُرفض
بـE910 حتى يوجد provider-owned constructor protocol. ABI v5 يشمل kinds
في هوية bridge ويعيد بناء كاش v4 حتى مع checksum قديم صحيح.

الاختبارات: 15 declaration بلغة قدس، و17 حالة رفض، وconstructor boundary،
وVM/JS مع 22 سطرًا متطابقًا وgolden، وترقية كاش فعلية. نجح الفحص المركّز
الأولي 109 اختبارات؛ بعد تصحيح توافق callbacks والبواني نجح فحص 67 حالة ثم
69 حالة. نجح الفحص النهائي للـparser والمعاملات: 32 اختبارًا في 41s.
نجح الفحص الشامل: **726 اختبارًا في 12m31s**، والتحليل نظيف والتنسيق
102 ملف دون تغييرات. النتيجة المثبتة في VALIDATION.md.
العقد: [QUDS_PARAMETER_FORMS.md](QUDS_PARAMETER_FORMS.md).

تعارض تنفيذي معروف لا يغيّر المواصفة: direct calls القديمة تسمح بتمرير
`name: Type = expr` موضعيًا. تبقى هذه السماحية في هذه الدفعة، بينما يحفظ
AST النوع optionalNamed ومراجع الدوال تطبّق named-only. لا يُعلن اكتمال
QUDS-022 أو جميع parameter forms؛ حالتها الآن partial في inventory.

### خطوات الاستلام التالية

1. وسّع provider packet ABI لتمثيل optional positional gaps، ثم أزل E910
   للاحتفاظ بالقيم المتروكة دون نقل defaults الخاصة إلى المستدعي أو تكرارها.
   قيم الدوال المخزنة تحتاج كذلك وسيلة آمنة لحفظ omission/default metadata.
2. أضف provider-owned constructor defaults: lexical scope وearlier-parameter
   rules وexactly-once وخصوصية وconst/super/generic signatures. اختبر كل مسار
   بقدس ثم VM/JS؛ لا تكتفِ بنسخ تعبير default في emitter المستدعي.
3. وحّد parameter parser للـlambdas، مع حفظ contextual inference والـcaptures.
   mixed optional groups ليست توقيع Dart واحدًا؛ تحتاج قرار lowering متوافقًا
   مع المواصفة، لا محو الأسماء أو optionality ولا Function.apply.
4. دقّق استدعاءات SDK والأمثلة، ثم طبّق optionalNamed matching على direct
   calls والـoverloads والـholes/spreads. ميّز سياسة الباني المولّد من fields
   عن parameter declarations؛ لا تغيّر API أو الصياغة المعتمدة بصمت.
5. وسّع override kind compatibility باختبارات widening الآمن؛ التنفيذ الحالي
   يشترط kind مطابقًا، وهذه فجوة توافق وليست تعديلًا لقاعدة override.
   حافظ على فحوص callback containers: ordinary positional types لا تحمل
   labels داخل التمثيل القديم. أي تطبيع بنيوي جديد يحتاج اختبارات invariance
   وnullability وgeneric inheritance؛ لا تنسخ kind إلى نص التوقيع فقط.
6. بعد كل دفعة: format/analyze/full tests وgolden وcache epoch عند الحاجة،
   ثم VALIDATION.md وinventory ورفع origin/main. اعتماد CI/Flutter والأداء
   وforeign implementors وبقية القيود موضح في الأقسام التاريخية أدناه.

## الدفعة الحالية: واجهات عامة وتواقيع مرتبطة بالمكتبة — مكتملة ضمن نطاقها

الأساس `21f2538`. نُفذت خطط forwarding متخصصة لكل implements edge،
بما فيه وراثة الواجهات، مع معاملات owner وmethod بأسماء backend مستقلة.
تحتفظ bounds التابعة للـowner بمعناها، وتظل defaults داخل provider.
الأنواع المعرفة في provider والـaliases تُؤهّل قبل نقل التوقيع. التواقيع
المختبرة تشمل records وcallbacks. إصلاح استنتاج الأنواع يحمي binder الدالة
من alias في مكتبة المستدعي يحمل الاسم نفسه. لا تغيير للصياغة المعتمدة.
ABI v4 يعيد بناء الكاش الأقدم تلقائيًا، حتى لو كان checksum القديم صحيحًا.

نجح فحص قدس الأساسي: **35 declaration**. نجح driver المركّز: **9 اختبارات**،
تشمل تنفيذ VM/JS متطابقًا، golden، رفض bounds غير المطابقة، قيود readonly،
والكاش. نجح الفحص الشامل: **705 اختبارات في 10m07s**، مع تحليل نظيف
وتنسيق 101 ملف دون تغييرات. النتائج الدقيقة في VALIDATION.md.
العقد وحدوده موثّقان في [QUDS_INTERFACE_DEFAULTS.md](QUDS_INTERFACE_DEFAULTS.md).

### المهمة التالية: metadata المعاملات من AST حتى ABI

المرجع هو فقرة parameterList في المواصفة 1.2: `name: Type` يقبل position
أو name، و`name: Type required` named-only required، و`name: Type = expr`
named-only optional، و`[parameters]` optional positional مع السماح بالاسم.
المحلل الحالي يستهلك `required` دون حفظه في Parameter، ولا يحفظ bracket
metadata. لا تصلح ذلك في emitter وحده ولا تغيّر المواصفة لتناسب التنفيذ.

1. أضف kind واضحًا إلى Parameter مع source span، واحفظه في parser وفي كل
   نسخ Parameter بالتحليل الدلالي، بما فيها imported/class/constructor signatures.
2. طبّق matching واحدًا للـdirect calls والـoverloads والـfunction values؛ اختبر
   named-required وoptional positional والازدواج والأسماء المجهولة وholes/spread.
3. راجع function-type encoding والتوافق وoverrides، وجميع جسور defaults
   والمكتبات المستوردة والـreadonly، ثم emitter. احفظ ترتيب التقييم مرة واحدة.
4. اعزل تحديث ABI والكاش في الدفعة ذاتها. أضف Quds positive/negative واختبار
   VM/JS وgolden وcache upgrade، ثم format/analyze/full tests وحدّث هذه الخطة.
5. التواقيع العامة/union/intersection المركبة وforeign Dart implementors
   وparts/cycles/conditional exports وإطارات debugger وأرقام الأداء تبقى
   بنود اعتماد مستقلة. لا تعلن اكتمال القواعد الـ115 من نجاح هذه الشريحة.

## الدفعة الحالية: جسور الواجهات — مكتملة ضمن نطاقها

الأساس `6beeeac`. الهدف هوية مستقرة لمراجع نفس عقد الواجهة، مع defaults
من مكتبة الواجهة وجسم method افتراضي dispatch إلى التنفيذ. دالة resolver في
provider تعيد record بالقيم المحلولة، وكلاس التنفيذ يوفّر عضو bridge يمرّرها
للطريقة الأصلية. readonly proxies توفّر الأعضاء نفسها. البداية بواجهات بلا
معاملات نوع، وتواقيع core/معاملات method المدعومة، دون تغيير قبول التواقيع
الأخرى. وراثة الواجهات وتعدد العقود والخصوصية والnullable تحتاج اختبارات قدس
وgolden وVM/JS قبل الرفع. نرفع ABI إلى v3 لترقية الكاش تلقائيًا.

نجحت الشريحة في اختبارات قدس: 30 declaration، تشمل multiple contracts
والـreadonly وnull/missing وgetters الحية وفشل default قبل دخول الجسم،
ومعاملات method عامة بأسماء مختلفة عن التنفيذ. التواقيع غير المشمولة تبقى
على المسار السابق؛ يوجد اختبار قبول لواجهة عامة بالأنواع نفسها.
أُصلح بحث الأب/المزيج المستورد باستخدام هوية نوع provider، فلا تفقد مراجع
الطرق الموروثة metadata الخاصة بـdefaults. استُعملت أسماء محجوزة لحزم الوسائط
حتى لا تُحجب native aliases مثل values.

نجح 129 اختبارًا مركّزًا في 27 ثانية. golden وتحليل وتنفيذ VM/JS متطابق في
93 سطرًا. اختبار ABI v2 إلى v3 يحافظ على checksum صالح لملف بلا جسور
الواجهة ثم يثبت أن quds run يعيد بناءه. الفحص الشامل النهائي: **704 نجاحًا،
دون فشل أو تخطٍّ، في 9 دقائق و42 ثانية**. أُعيد مشغّل المحوّلات بعد تنظيف
import مكرر، ونجحت اختباراته الثمانية في 15 ثانية. التنسيق (101 ملف) والتحليل
وفحص السجل ومزامنة الكلمات ناجحة. مثال مكتبتين عبر quds run طبع 70 و40 وtrue.
العقد وحدود الشريحة في [QUDS_INTERFACE_DEFAULTS.md](QUDS_INTERFACE_DEFAULTS.md).
التالي: توسيع declaring-interface generics والأنواع ذات الارتباط بالمكتبة
مع binder hygiene، ثم توحيد metadata للمعاملات. لا تغيّر syntax لتوسيع البوابة.


## الدفعة الحالية: طرق المكتبات المستوردة — مكتملة ضمن نطاقها

الأساس `35d41c5`. نوسّع ABI provider إلى الطرق العامة ذات defaults في
الكلاسات العادية، مع أسماء أعضاء مستقرة مرتبطة بالنوع المعلِن. يجب إصدار
الجسور من provider ولو لم يستعمل tear-off محليًا، وتوفير الأعضاء في readonly
proxies. الاختبارات تشمل private fields/helpers وDart aliases وgeneric وstatic
والوراثة وnullable وتقييم receiver مرة واحدة. الواجهات تبقى على عقدها السابق.

أُصلح نطاق تحليل الطريقة المستوردة ليحفظ alias المكتبة والحقول الخاصة؛
فحص private يستعمل مكتبة التعريف النشطة، مع استعادة سياق التحليل عند الخروج.
اختبارات المستورد السالبة ما زالت ترفض private fields/methods. أُضيف كذلك
short-circuit ونتيجة nullable للاستدعاءات الآمنة للطرق المشمولة، فلا تعمل
الوسائط ولا defaults عند null. لا تُخفَّف قيود readonly لنتيجة generic قابلة للتعديل.

نجح 128 اختبارًا مركّزًا في 28 ثانية. مجموعة قدس 22 declaration، والمشغّل
يتحقق من ترقية ABI v1 إلى v2 مع checksum صالح للملف القديم. Golden وتحليل
وتنفيذ VM/JS متطابق في 60 سطرًا. الفحص الشامل النهائي: **703 نجاحًا دون
فشل أو تخطٍّ في 9 دقائق و33 ثانية**. التنسيق (101 ملف) والتحليل الساكن
وفحص سجل القرارات ومزامنة الكلمات ناجحة. مثال مكتبة منفصلة نفّذ quds run
وطبع true و11 وQuds و12 و7. النتائج المفصلة في VALIDATION.md.
العقد في [QUDS_PROVIDER_DEFAULTS.md](QUDS_PROVIDER_DEFAULTS.md).
الخطوة التالية: جسور الواجهات، ثم metadata للمعاملات، ثم بقية أشكال provider
والـreadonly/variadic/intersection غير المشمولة. لا تُعلن دعمها من نجاح هذه الشريحة.

النداءات المباشرة ذات defaults ستستعمل الجسر أيضًا، دون تغيير قبول syntax
القديم. نرفع ABI الكاش إلى v2، ثم نختبر قدس وgolden وVM/JS والفحص الشامل قبل الرفع.

## الدفعة الحالية: جسور دوال المكتبات — مكتملة ضمن نطاقها

الأساس `f42d8ce`. سنصدر bridge عامًا ثابت الاسم من provider للدوال العامة
ذات defaults والتوقيع المعلن المدعوم. يبقى حساب default داخل نطاق provider؛
لا ننقل AST لدالة خاصة أو alias لـDart إلى المستورد. الاختبارات ستشمل
use ببادئة وبدونها وshow/export، وتساوي المراجع وترتيب defaults وgeneric،
ثم تحليل Dart وVM/JS والفحص الشامل. طرق المكتبات والواجهات وSDK signatures
المعقدة ليست مشمولة قبل عقودها المنفصلة. النتائج تُسجّل قبل الرفع.

أُضيف مسار الاستدعاء المباشر عندما يحذف default كذلك: تُحفظ الوسائط المكتوبة
بالترتيب أولًا، ثم ينفذ الجسر defaults في provider. لا يتغير قبول الوسائط
الموضعي القديم هنا؛ توحيد metadata يبقى خطوة منفصلة.

نجح 127 اختبارًا مركّزًا في 25 ثانية. مجموعة قدس 18 declaration، والمشغّل
النهائي ستة اختبارات، مع golden وتحليل وتنفيذ VM/JS متطابق في 45 سطرًا.
كشف الفحص الشامل إدخال بعض أقسام SDK في ABI الجديد، فاستُبعدت بحسب ملفاتها
المحمّلة، ونجحت اختبارات foundations والمحوّلات السبعة على المصدر المصحّح
خلال 9 ثوانٍ. أُعيد الفحص الشامل من البداية؛ التشغيل الموقوف ليس شهادة نجاح.
العقد وحدود الدعم في
[QUDS_PROVIDER_DEFAULTS.md](QUDS_PROVIDER_DEFAULTS.md).
نجح الفحص الشامل للمترجم قبل تحديث الكاش: 702 نجاحًا في 9 دقائق و36 ثانية.
أُضيف بعده إصدار ABI للكاش (`provider-defaults-v1`)، حتى يعاد بناء provider
القديم تلقائيًا دون حذف يدوي للكاش. اختبار الترقية يحتفظ بـchecksum صالح
لملف بلا bridges، وقد نجح المشغّل النهائي بسبعة اختبارات خلال 13 ثانية.
الفحص الشامل الأخير بعد تحديث الكاش: **703 نجاحًا، دون فشل أو تخطٍّ،
في 10 دقائق و6 ثوانٍ**. التحليل الساكن والتنسيق (101 ملف) وفحص سجل
القرارات ومزامنة الكلمات وفحص whitespace ناجحة. هذه نتيجة المصدر النهائي.
عند إضافة ABI غير متوافق لاحقًا حدّث `_generatedAbi` في bin/quds.dart،

## دفعة مراجع القيم والاستيراد المؤجل — عمل هذا العامل للمراجعة

### ما دخل المترجم

- قيمة دالة أو طريقة ذات وسيط افتراضي تُخزَّن كإغلاق Dart. الحذف يستخدم الحارس
  `missing`، ويبقى مختلفًا عن `null` الصريح. الافتراضي المحسوب ما زال يشير
  إلى المعاملات السابقة فقط. الاستدعاء المباشر يملأ الافتراضي في موقع النداء؛
  الإغلاق يُنشأ عند تخزين القيمة.
- القيمة المتغيرة `(...items: T) -> R` تُخفَّض إلى `R Function(List<T>)`.
  موقع النداء يحزم الوسائط والنشر، بما في ذلك القائمة الفارغة.
- معامل intersection يُبقي معامل نوع Dart المخفي وفحص `is!` وقت التشغيل.
  نوع الدالة الذي يحتوي `&` أو `|` لا يُقسَّم قبل التعرف على شكل الدالة.
- طريقة بلا معاملات تعيد مجموعة readonly تُلفّ بحارس عند أخذ مرجعها. طريقة
  لها معاملات وما زالت تحتاج الحماية نفسها تبقى E910.
- مرجع أو نداء static موروث يُصدر نوع المُعلِن (`Utility.echo`) لأن Dart لا
  يورّث الأعضاء الثابتة. هذا تخفيض تنفيذي، لا تغيير لقاعدة الوراثة.
- مجموعة overload مستوردة بتواقيع مختلفة تنشر `name$1` و`name$2` بترتيب المصدر.
  التوقيع المكرر أو تصادم الاسم مع كلاس يبقى E204.
- `use uri as prefix deferred` ثم `await prefix.loadLibrary()`. الاستيراد
  المؤجل بلا بادئة مرفوض. `loadLibrary` على بادئة غير مؤجلة هو E300.
- طريقة extension عامة تدخل معاملاتها النوعية النطاق قبل فحص الأنواع، ويمكن
  تخزينها كقيمة عندما تحتاج محوّلًا.

معامل مطلوب أو variadic بعد افتراضي يبقى E910: لا إغلاق موضعي واحد في Dart
يمثّل هذا الشكل. الجمع بين افتراضي وvariadic في القيمة نفسها داخل هذا الشكل
مرفوض كذلك.

## 3. سلامة الأنواع والذاكرة

أُبقي رفض تجاوز `readonly` عبر مراجع methods الأجنبية؛ لا يكفي أن Dart يقبل
الكود كي يكون آمنًا وفق قدس. الباقي مراجعة حدود FFI والدوال الأجنبية، والتحويل
بين الواجهات المقروءة والمتحولة، وتسرب dynamic، وaliasing في الرسوم المتداخلة.
استعمل اختبارات `.quds` لإثبات الرفض والسلوك قبل تغيير compiler/emitter.
إدارة الذاكرة التنفيذية تعتمد على Dart؛ أي ادعاء أداء أو توفير ذاكرة يتطلب
قياسًا متكررًا ببرنامج وبحجم بيانات واضحين، لا استنتاجًا من نجاح الترجمة.

## 4. المكتبات والاستيرادات والبيئة المستهدفة

أُصلح اختيار الاستيرادات الشرطية: `platform` لم يعد VM دائمًا عند بناء الويب.
واجهة `compile` تقبل `targetPlatform` بقيم `vm` و`web` و`flutter`، و`flutter`
لتحديد توافر واجهة UI. المشاريع ذات Flutter SDK تُكتشف من YAML الفعلي.
`dart.library.io` و`dart.library.js_interop` يتبعان الهدف، و`dart.library.ui`
يتبع توافر Flutter. `when:` على مستوى الملف يسمح بتوجيهات `use` داخل الفرع.
الفرع غير المختار لا يُحمّل ولا يُفحص؛ له اختبارات بملف غير صالح عمدًا.

`quds build web` و`quds run -d chrome` وF5 مع `deviceId: chrome` تختار الويب.
عند عدم تحديد جهاز، يكون الافتراض Flutter أصليًا؛ تحديد backend بناءً على
اختيار Flutter التفاعلي للجهاز ليس معتمدًا بعد. استخدم `-d chrome` أو
`-d web-server` للكود الذي يتغير حسب المنصة. فحص المحرر الافتراضي لمشروع
Flutter لا يمثل كل أجهزة المشروع في وقت واحد؛ توحيد إعداد الهدف بين LSP
والبناء وجلسة التصحيح بند باقٍ.

الباقي: deferred imports بتغطية loadLibrary وتوقيت التهيئة والأخطاء، والتعبئة
والنشر لمكتبات قدس مع Dart المولّد، وحالات التصدير/الأجزاء/الدورات عبر الحزم.
لا تستحدث صياغة جديدة قبل مراجعة المواصفة والسلوك المعتمد.

## Function-value metadata follow-up — 2026-11-18

Native non-generic function and method values now preserve optional positional
and required/optional named parameters, including nested native callback types.
Structural annotations use the approved parameter grammar, for example
`([value: int = 0]) -> int` and `(value: int required) -> int`.
A default in a function type records optionality; it does not replace the
underlying callable's default. Native defaults execute in Dart when omitted;
explicit null remains explicit null. Function subtyping checks parameter kinds,
labels, omission and contravariance. Reordered calls capture the callable and
arguments exactly once in source order. Earlier optional/named limitations in
this document are superseded for this slice. Generic function values, richer
record signatures and full Quds declaration/lambda parameter-form parity remain
unfinished. Tests: native_function_values.quds (eight declarations), fourteen
negative cases, deterministic Dart golden, actual Dart analysis and VM/JS runs.
