# مراجعة مراجع طلبات السحب — 2026-11-19

أساس المراجعة: `origin/main` عند `8ff6de8946973619d85d6c6710977f6b076cdc90`.
طلب المالك: مراجعة الطلبات المفتوحة، ودمج المفيد بأمان، وإغلاق غير اللازم.

## قيد الوصول وحالة التنفيذ

Git fetch وقراءة مراجع الطلبات يعملان. لكن `gh pr list` عبر GraphQL و`gh api`
عبر REST يعيدان `Forbidden`؛ سياسة الشبكة الفعلية لا تسمح بـ`api.github.com`.
صفحة المستودع غير الموثقة تعيد 404. لذلك **لم تُقرأ قائمة الطلبات المفتوحة
قراءة موثوقة، ولم يُنفذ دمج أو إغلاق من GitHub**. مراجع `refs/pull/*/head`
تبقى بعد دمج الطلب أو إغلاقه، ولا يجوز عدّها قائمة الطلبات المفتوحة.

القرارات أدناه مراجعة للمحتوى المتاح عبر Git. بعد إتاحة API يجب قراءة الحالة
الفعلية وإعادة التحقق من SHA لكل طلب قبل إجراء أي تعديل. لا حذف للفروع.

## نتائج مراجعة #17 (`1099a08`)

### 1. انهيار runtime جديد في كاش مراجع extensions

المثال نفسه شُغّل على فرع الطلب وعلى main، في مجلدَي إخراج منفصلين:

```quds
extend Object:
  inspect(value: int = 1) -> int = value
main():
  item: Object = 3
  saved = item.inspect
  print saved()
```

- main عند `8ff6de8`: يطبع `1`.
- رأس #17: يفشل عند أخذ المرجع برسالة:
  `Invalid argument (object): Cannot be a string, number, boolean, record, null, Pointer, Struct or Union: 3`.
- السبب: `_canCacheReceiver` يسمح بالنوع الساكن Object، ثم `_cachedExtensionValue`
  يستخدم Expando على القيمة الفعلية العددية. استبعاد الاسم int وحده لا يثبت
  أن Object أو معامل نوع عام سيحمل كائنًا يقبله Expando.

### 2. قبول مخالف للمعامل الاختياري المسمى

```quds
choose(value: int = 1) -> int = value
main():
  print choose(2)
```

- main يرفض النداء بـE500 عند مصدر قدس؛ الشكل الصحيح `choose(value: 2)`.
- رأس #17 يقبل النداء ويطبع `2`.
- وصف الطلب يعترف بالإبقاء على الاستثناء القديم لأجل SDK. main تجاوز ذلك
  الاستثناء وهاجر نداءات SDK. لذلك لا يُستعاد هذا القبول عند حل التعارضات.

### 3. تعارض مع التنفيذ الأحدث

`git merge-tree --write-tree --name-only origin/main origin/pr/17` وجد تعارضات
في 15 ملفًا: ABI في CLI، وAST وparser وsemantics وemitter، والوثائق وفهرس
الجاهزية، واختبارات المعاملات والوراثة ومساعداتها. لم يُعدل worktree الرئيسي
بهذا الفحص. رأس الطلب يستعمل ParameterPassing وABI v3، بينما main يستعمل
ParameterKind وABI v10، مع إصلاحات defaults وawait والنتائج المستنتجة.
لا يصلح اختيار نسخة أحد الجانبين لحل هذه التعارضات.

اختبارات المعاملات الأربعة الموجودة في فرع #17 تنجح، لكنها لا تكشف المثالين
أعلاه. لذلك نجاحها وحده ليس سببًا لدمج الطلب.

## ما يجب حفظه من #17 لمتابعة مستقلة

- توسيع جسور defaults إلى value/mixin والطرق المحمية، مع الحفاظ على الخصوصية
  ونطاق الإعلان وتوافق readonly ووراثة البروتوكول الحالي.
- هوية مراجع extensions على الكائنات المؤهلة، وهوية defaults مع intersection.
  يجب اختبار Object الذي يحمل primitive، والأنواع العامة، والنتيجة readonly،
  وتخصصات النوع والمستقبلات المختلفة قبل اختيار آلية الكاش.
- الحفاظ على اختبارات الواجهة/التنفيذ ذات الافتراضيات المختلفة، والمساواة
  والتقييم مرة واحدة، دون استرجاع ABI أو صياغة المعاملات القديمة.

أما overloads الطرق، وdefault مع variadic، وحراسة نتيجة readonly ذات معاملات،
وتركيب مُنشئ الأب في الشريحة المدعومة فلها تنفيذ أحدث وأوسع في main. تُراجع
الفروق الدقيقة قبل نقل أي حالة اختبار، ولا يُنسخ تنفيذها القديم فوق الجديد.
