# خارطة توسيع رياضيات قدس

تاريخ التحديث: 2026-11-15.

## المقصود بالتوسعة

الهدف أن تصبح قدس منصة رياضية تغطي احتياجات التعليم والبحث والحوسبة العلمية:
ما توفره `dart:math`، وما أضافته `quds:math`، والفروع التي لا تغطيها أي منهما
حاليًا. لا يوجد نطاق منتهٍ باسم «كل الرياضيات» يمكن إعلان اكتماله؛ لذلك نقيس
التقدم بعقود واضحة لكل عائلة، ومسائل مرجعية قابلة للتنفيذ، ودرجات نضج موثقة.
هذه خريطة تطوير، وليست ادعاءً بتنفيذ الصفوف الآتية كلها.

المقارنة هنا مع مكتبة Dart القياسية، وليست مسحًا لكل حزم pub.dev. وجود حزمة
خارجية مناسبة قد يوفر تنفيذًا أو مرجعًا؛ لا يعني ذلك أن API لها متاح في قدس
قبل التحقق من الترخيص والتكامل والدقة والمنصات والصيانة.

تكمّل هذه الوثيقة [خطة تعزيز الدقة](MATH_STRENGTHENING_PLAN_AR.md).
تبدأ أي عائلة جديدة بعقد واختبارات مرجعية، بالتوازي مع تقوية الموجود؛ لا
نؤجل ضبط الدقة حتى تكتمل التوسعة، ولا نشترط اكتمال كل العقود القديمة قبل
إضافة عائلة مستقلة مثل الرسوم. لا يتغير تصميم اللغة 1.2 بهذه الخطة.

## كيف نختار موضع التنفيذ

1. نعيد استعمال Dart القياسي حين يفي بالعقد، ونحافظ على الأسماء المعتمدة:
   `log` للتسجيل و`ln` للوغاريتم الطبيعي، مع سلوك prefix الحالي.
2. ننفّذ الخوارزميات المكتبية في Quds حيث يسمح المترجم بذلك؛ يبقى المصدر
   `lib/sdk/math.quds` مرجعًا وتُولّد نسخته المضمنة بأداة التزامن.
3. نستعمل حزمة Dart خارجية فقط بعد توثيق الترخيص والدقة وتوافق VM/JS وحجم
   الاعتماديات، واختبارها من برنامج Quds حقيقي. لا نضيف حزمة تلقائيًا لمجرد
   أن اسمها يوحي بتغطية مجال كامل.
4. نخصص واجهة native/FFI اختيارية للأعمال الثقيلة إذا أثبت القياس حاجتها؛
   لا نجعل اعتمادًا غير متاح في الويب شرطًا لاستيراد الرياضيات الأساسية.
5. الحساب الرمزي وAD وinterval مكتبات ذات عقود رياضية جديدة؛ لا تحتاج syntax
   جديدًا أو تغيير دلالات `double` أو `int` أو المعاملات القائمة بصمت.
6. نقيّم فصل الوحدات بعد اختبار loader والخصوصية وتغليف الحزمة. أسماء مثل
   `quds:math/graph` أفكار تنظيمية، **ليست مسارات استيراد منفّذة الآن**.

## مراحل التنفيذ

### A — أساس التوسعة

- تثبيت خريطة API وعقود كل حزمة جديدة ودرجة نضجها.
- اختبار الرفض والحدود والملكية والنسخة المضمنة والمنصات.
- توثيق اعتماديات كل مجال، والتمييز بين approximate وexact وsymbolic.
- بوابة القبول: استيراد حقيقي من Quds وDart، نتائج مستقلة، صفر فشل مخفي.

### B — الرياضيات المتقطعة والحساب الدقيق

- **B1: الرسوم غير الموزونة**: الحزمة المنفذة أدناه.
- **B2: الرسوم الموزونة**: تمثيل حواف يحفظ الرؤوس المعزولة والحواف المتوازية؛
  أوزان finite، وعقد Infinity للبعد غير المتاح. Dijkstra يرفض السالب؛
  Bellman–Ford يميز دورة سالبة قابلة للوصول؛ MST يقبل الرسم غير المتصل كغابة
  بعقد صريح. المراجع: تعداد مسارات/أشجار الرسوم الصغيرة ومقارنة مستقلة.
- **B3: الحساب الدقيق**: إثبات دعم BigInt وعملياته في interop أولًا، ثم كسور
  مطبّعة ومتتاليات توافقيّة دون overflow. اختبارات مقارنة exact على VM/JS.
- **B4: التدفق والمطابقة**: residual graph وحدود السعات وعقد min-cut، ومراجع
  brute-force للرسوم الصغيرة. منفصل عن الأوزان الحقيقية للمسافات.

### C — التفاضل الآلي والهندسة

- **C1: forward AD**: dual numbers، البذور الاتجاهية، chain rule، مجالات
  log/sqrt/pow ونقاط عدم القابلية للاشتقاق، دون finite differences مخفية.
- **C2: gradient/Jacobian/Hessian**: shapes وترتيب المتغيرات وتكلفة الاستدعاء
  وإدارة side effects، ثم reverse AD بوحدة مراجعة منفصلة.
- **C3: هندسة حسابية**: predicates أولًا قبل بناء hull/intersection عليها؛
  شبه التوازي والقيم متعددة المقاييس تقارن بحساب دقيق مستقل.
- بوابة القبول: مشتقات تحليلية ومراجع عالية الدقة واختبارات domain، ودليل
  واضح على ما تعيده الخوارزمية عند النقاط غير الملساء.

### D — الحوسبة العلمية والإحصاء المتقدم

- sparse matrices ومنع نسخ المصفوفة لكل تحديث داخلي، مع residuals مقاسة.
- ذيول التوزيعات وweighted/streaming statistics وmultivariate distributions.
- تحسين مقيد وLP phase-I، ثم stiff ODE وSDE/PDE في حزم صغيرة.
- تحويلات وإشارات وسلاسل زمنية، باتفاقيات normalization موثقة.
- بوابة القبول: دراسات تقارب وتكييف واختبارات إحصائية ببذور وحدود إنذار
  زائف محددة، وbenchmarks بعد ضمان الصحة.

### E — الحساب الرمزي والجبر المتقدم

- عقد تعبيرات رمزية بقيم دقيقة وافتراضات على الرموز؛ لا تحليل نصوص بالتعابير
  النمطية، ولا خلط expression AST الرياضي بقواعد parser اللغة.
- substitution وcanonicalization محافظان؛ `sqrt(x*x)` لا يساوي `x` لجميع
  القيم، و`x/x` يحتاج شرطًا، وفروع complex لا تختفي عند التبسيط.
- اشتقاق ثم كثيرات حدود متعددة المتغيرات وتحليل عوامل، ثم تكامل محدود
  القواعد وحل رمزي يعيد «غير مدعوم» أو شروط الحل بدل جواب مختلق.
- لاحقًا finite fields والجبر التجريدي وcomputational topology والمنطق،
  وفق حالات استعمال ومراجع مستقلة لكل فرع.

لا تمثل هذه المراحل موعد تسليم أو تنفيذًا تلقائيًا لكل خوارزمية في جلسة واحدة.
التسليم يكون بحزمة كاملة قابلة للمراجعة، ثم تحديث الخريطة والأدلة.

## الحزمة الأولى: الرسوم غير الموزونة

أضيفت إلى `quds:math` الدوال التالية؛ تفاصيلها في [MATH_GRAPH.md](MATH_GRAPH.md):

| API | العقد |
| --- | --- |
| `transposeGraph` | عكس اتجاه الحواف مع حفظ التكرار والرؤوس المعزولة |
| `bfsDistances` | مسافات صحيحة غير موزونة، و`-1` لغير القابل للوصول |
| `shortestUnweightedPath` | مسار أقصر، أو قائمة فارغة عند عدم وجوده |
| `weaklyConnectedComponents` | مكوّنات الاتصال بعد تجاهل الاتجاه |
| `stronglyConnectedComponents` | مكوّنات الوصول المتبادل، ببحث تكراري دون recursion |
| `topologicalSort` | ترتيب DAG حتمي، ورفض صريح للدورات |
| `bipartiteColoring` | تلوين الرسم غير الموجّه الضمني، ورفض الدورات الفردية |
| `transitiveClosure` | مصفوفة الوصول الانعكاسي، تشمل المسار بطول صفر |

التحقق يجمع 13 اختبار استعمال بصياغة قدس، ومراجع مستقلة باستخدام
Floyd–Warshall وتعداد جميع التلوينات الثنائية على رسوم صغيرة، وفحص سلسلة
من 20 ألف رأس، و119,740 فحصًا على كل من VM وJavaScript دون إخفاق. نتائج
التحقق الكاملة تسجل في
[VALIDATION.md](VALIDATION.md) بعد تشغيل الفحوص.

الخطوة التالية المقترحة هي B2 بعقدها أولًا، ثم B3 وC1؛ لا نعدّ هذه الإضافة
تنفيذًا للحساب الرمزي أو الرياضيات الموزونة أو بقية الخريطة.
