# خطة اكتمال لغة قدس وأدواتها

هذا الملف نقطة استلام للعميل التالي. مواصفة اللغة **1.2** هي المرجع، وإصدار
حزمة المترجم مستقل عنها. لا تغيّر الصياغة المعتمدة لتجاوز مشكلة تنفيذية.
الهدف توافق موثّق مع Dart وتجربة تطوير متكاملة، وليس إضافة صياغة خاصة بفلاتر
إلى قلب اللغة. هذه دفعة أولى من الخطة، وليست إعلان اكتمال البنود التسعة.

## تسليم الدفعة الحالية: مراجع دوال قدس واختيار overload

الحالة: مكتملة ومختبرة ضمن هذا التعديل؛ الدفعة المنشورة السابقة `c0f3c7c`.

الهدف: تخصيص الدوال العامة المعرفة بقدس بمعاملات نوع صريحة أو بتوقيع متوقع،
واختيار مرجع واحد من overload محلي بالتوقيع المتوقع. الغموض E311 وفق المواصفة؛
لا اختيار صامت لأول تعريف. ابدأ بالدوال العادية ذات المعاملات المطلوبة؛
تكييف defaults/variadics وطرق الكلاسات ومراجع overload المستوردة تحتاج عقودًا
إضافية ولا تُعلن مكتملة بهذه الدفعة.

الملفات: semantics.dart وemitter.dart واختبارات قدس موجبة وسالبة جديدة.
الفحص: Dart golden، تحليل وتنفيذ VM/JS، ثم format/analyze/dart test كاملًا.
حدّث هذا التسليم وVALIDATION.md وارفع الدفعة المختبرة إلى main.

أُضيفت مجموعة `test/quds_function_values.quds` (خمسة declarations)، ومشغّل
بـ14 حالة رفض وDart golden وتنفيذ VM/JavaScript متطابق في 14 سطرًا.
نجح 124 اختبارًا مركّزًا في 14 ثانية؛ الفحص الشامل النهائي 677 نجاحًا
دون فشل أو تخطٍّ في 9 دقائق و48 ثانية. التنسيق والتحليل وفحص السجل ناجحة.
العقد والأمثلة وحدود الدعم في [QUDS_FUNCTION_VALUES.md](QUDS_FUNCTION_VALUES.md).

ما يبقى بعد هذه الدفعة: adapters للقيم الافتراضية وvariadics وintersection،
ومراجع طرق كلاس/extension قدس مع تعويض نوع الكائن، وتصدير واستيراد مجموعات
الـoverload بأسماء ثابتة. الاستيراد الحالي لمجموعة overload يرفض تكرار الاسم
بـE204؛ استيراد الدالة المفردة المجرّب هنا ذو نوع نتيجة معلن. نشر metadata
لنتيجة provider المستدل عليها، وحل قيود الأنواع الكامل، يحتاجان عملًا إضافيًا.


## الدفعة السابقة: الاستدلال السياقي لمراجع دوال Dart العامة

الحالة: مكتملة ومنشورة في `c0f3c7c`؛ الدفعة التي سبقتها `06171c2`.

الهدف قبول `saved: (int) -> int = native.identity` واستعمال مرجع عام في
موضع callback ذي توقيع معلوم، دون كتابة معاملات النوع صراحةً. يجب التحقق من
التوقيع والحدود والتباين بعد الاستدلال، وحفظ الوسائط الاختيارية والمسمّاة
والـnullable وتقييم receiver مرة واحدة. السياق المفقود أو المتعارض لا يسمح
باختيار dynamic صامت. لا تشمل الدفعة callbacks متعددة الأشكال ولا Quds overloads.

الملفات: semantics.dart وemitter.dart واختبارات native_function_values.
معيار الإغلاق: قدس موجبة وسالبة، Dart golden وتحليل وتنفيذ VM/JS، ثم format
وanalyze والفحص الشامل، وتحديث VALIDATION.md وهذا التسليم قبل الرفع إلى main.

نجحت الاختبارات المركّزة: 120 اختبارًا في 18 ثانية. مجموعة قدس 13 declaration،
مع ناتج Dart مرجعي وتحليل وتنفيذ VM/JS، وتشمل alias باسم T عند المستدعي،
والحدود، والتباين، وFuture، والمعاملات المسمّاة بترتيب مختلف، وreceiver nullable.
الفحص الشامل النهائي: 661 نجاحًا، صفر فشل أو تخطٍّ، في 9 دقائق و44 ثانية.
التنسيق والتحليل الساكن وفحص سجل القرارات ناجحة.

آلية التنفيذ: أسماء مستقلة لمعاملات native أثناء الاستدلال، ثم إصدار معاملات
النوع صراحةً في Dart. السياق المفقود يبقى E910، والسياق الوظيفي الذي لا يحدد
كل المعاملات E302، والتواقيع المتعارضة أو الحدود المخالفة تُرفض في موضع قدس.

ما يبقى بعد هذه الدفعة:

1. استكمال حل قيود الأنواع ذات التباين المختلط وinstantiate-to-bound؛ الحل
   الحالي بنيوي ومحافظ، وقد تتطلب الحالات المعقدة معاملات نوع صريحة.
2. تخصيص مراجع دوال وoverloads قدس نفسها مع اختيار واضح ورفض الغموض E311.
3. تمثيل callbacks التي تبقى عامة بمعاملات نوع ذات binders مستقلة.
4. متابعة بقية مسارات المكتبات والمحرر والمنصات في الأقسام أدناه، دون الادعاء
   بأن مرور الاختبارات يُغلق القرارات الـ115.


## الدفعة السابقة: التخصيص الصريح لمراجع دوال Dart العامة

الحالة: مكتملة ومنشورة في `06171c2`؛ الدفعة التي سبقتها `f88ceac`.

- الهدف: قبول `saved = native.identity<int>`، ومرجع method عامة مرتبطة
  بكائن أو ثابتة، بعد تحديد معاملات النوع صراحةً.
- الحفاظ على التحقق من عدد معاملات النوع وحدودها، والتواقيع الاختيارية
  والمسمّاة، وتقييم الكائن مرة واحدة، ومواضع تشخيصات قدس.
- عدم افتراض `dynamic` للدالة العامة غير المخصّصة، وعدم الادعاء بدعم
  تواقيع callbacks العامة أو inference الكامل لمراجع الدوال العامة.
- أُضيف المسار مع اختبارات عشرة declarations بقدس، واختبارات رفض لتجاوز
  حدود النوع وعدد المعاملات والتواقيع غير المتوافقة. الاختبارات المركّزة:
  93 نجاحًا في 23 ثانية. الفحص الشامل النهائي: 653 نجاحًا، صفر فشل أو
  تخطٍّ، في 10 دقائق و3 ثوانٍ. التحليل الساكن والتنسيق وفحص السجل ناجحة.
- مثال مدعوم: `use dart:math as math` ثم `larger = math.max<int>`.
  الصياغة المعتمدة لم تتغير؛ تخصيص Quds overloads نفسه لم يُنجز في هذه الدفعة.
- الوصول nullable يولّد capture واحدًا للكائن وفحص null قبل تخصيص method،
  لتجاوز قيد Dart دون تغيير معنى `?.` أو تكرار تقييم الكائن.
- الملفات الأساسية: parser.dart، semantics.dart، emitter.dart، واختبارات
  native_function_values. يجب إضافة مثال قدس وتنفيذ VM/JS وناتج مرجعي.
- التحقق: format، analyze، الاختبارات المركّزة، ثم الفحص الشامل وتوثيق
  أي إخفاق وإصلاحه بدقة في VALIDATION.md؛ أُنجزت هذه الفحوص لهذه الدفعة.
- الخطوة التالية بعد هذه الدفعة: مراجعة inference من النوع المتوقع،
  وتواقيع callbacks العامة، دون توسيع الصياغة المعتمدة.

خطة الاستلام السابقة (أُنجز البند الأول في الدفعة الحالية أعلاه):

1. ابدأ بحالة `(int) -> int = native.identity` دون `<int>`: اثبت الاستدلال
   من السياق وحدود النوع، ورفض السياق الناقص أو المتعارض دون `dynamic` صامت.
2. راجع تخصيص مراجع دوال قدس وoverloads نفسها؛ مسار هذه الدفعة يقبل native
   فقط. استعمل اختيار overload المعتمد، واحفظ تشخيص الغموض E311.
3. عالج callbacks التي تبقى عامة بوصفها أنواعًا ذات binders ونطاق مستقل؛
   استبدال أسماء معاملات النوع نصيًا لا يكفي لإثبات التكافؤ أو السلامة.
4. اختبر تداخل معامل نوع الكلاس والطريقة، والمراجع readonly، وFuture،
   وتقييم receiver مرة واحدة، والتحليل والتنفيذ على VM/JS قبل إعلان الدعم.
5. لا تعِد نشر البيئة. حدّث هذا التسليم وVALIDATION.md وارفع الدفعة
   المختبرة إلى origin/main، دون force push أو نشر pub.dev ضمنيًا.

## 2. تكامل Dart

المنجز في هذه الدفعة:

- استعمال الدوال المستوردة ذات المعاملات الموضعية المطلوبة كقيم، بما فيها
  الدوال بلا معاملات، والدوال ذات بادئة الاستيراد أو بدونها.
- أخذ مرجع إلى method ثابتة أو مرتبطة بكائن، مع تعويض معامل نوع الكلاس.
- تقييم الكائن المرتبط مرة واحدة، والمحافظة على نتيجة الوصول الآمن nullable.
- رفض التواقيع غير المدعومة بـE910 بدل افتراض توقيع ديناميكي؛ منع مرجع method
  أجنبي غير موثوق عبر `readonly` بـE307.
- اختبارات الاستخدام الأساسية في `test/native_function_values.quds`، والتحليل
  والتنفيذ الفعلي على Dart VM وJavaScript في المشغّل المرافق.

مثال مدعوم:

```quds
use dart:math as math

main():
  sine = math.sin
  print sine(0.0)
```

الباقي: قيم الدوال الأجنبية generic، والقيم ذات المعاملات optional أو named،
والـcallbacks ذات الأشكال غير المدعومة، وتغطية records وtypedefs وextension
 types المتداخلة. ابدأ باختبار قدس صغير لكل توقيع، ثم وسّع metadata والتوحيد
النوعي والإصدار معًا. لا تُزل E910 قبل إثبات حفظ التوقيع والقيم الافتراضية
وترتيب التقييم. مسار API الأجنبي الذي لا تتوفر له metadata قد يبقى dynamic؛
لا نقدّمه بوصفه ضمانًا للتحقق الساكن الكامل.

## 3. سلامة الأنواع والذاكرة

أُبقي رفض تجاوز `readonly` عبر مراجع methods الأجنبية؛ لا يكفي أن Dart يقبل
الكود كي يكون آمنًا وفق قدس. الباقي مراجعة حدود FFI والدوال الأجنبية، والتحويل
بين الواجهات المقروءة والمتحولة، وتسرب dynamic، وaliasing في الرسوم المتداخلة.
استعمل اختبارات `.quds` لإثبات الرفض والسلوك قبل تغيير compiler/emitter.
إدارة الذاكرة التنفيذية تعتمد على Dart؛ أي ادعاء أداء أو توفير ذاكرة يتطلب
قياسًا متكررًا ببرنامج وبحجم بيانات واضحين، لا استنتاجًا من نجاح الترجمة.

## 4. المكتبات والاستيرادات والبيئة المستهدفة

أُصلح اختيار الاستيرادات الشرطية: `platform` لم يعد VM دائمًا عند بناء الويب.
واجهة `compile` تقبل `targetPlatform` بقيم `vm` و`web` و`flutter`، و`flutter`
لتحديد توافر واجهة UI. المشاريع ذات Flutter SDK تُكتشف من YAML الفعلي.
`dart.library.io` و`dart.library.js_interop` يتبعان الهدف، و`dart.library.ui`
يتبع توافر Flutter. `when:` على مستوى الملف يسمح بتوجيهات `use` داخل الفرع.
الفرع غير المختار لا يُحمّل ولا يُفحص؛ له اختبارات بملف غير صالح عمدًا.

`quds build web` و`quds run -d chrome` وF5 مع `deviceId: chrome` تختار الويب.
عند عدم تحديد جهاز، يكون الافتراض Flutter أصليًا؛ تحديد backend بناءً على
اختيار Flutter التفاعلي للجهاز ليس معتمدًا بعد. استخدم `-d chrome` أو
`-d web-server` للكود الذي يتغير حسب المنصة. فحص المحرر الافتراضي لمشروع
Flutter لا يمثل كل أجهزة المشروع في وقت واحد؛ توحيد إعداد الهدف بين LSP
والبناء وجلسة التصحيح بند باقٍ.

الباقي: deferred imports بتغطية loadLibrary وتوقيت التهيئة والأخطاء، والتعبئة
والنشر لمكتبات قدس مع Dart المولّد، وحالات التصدير/الأجزاء/الدورات عبر الحزم.
لا تستحدث صياغة جديدة قبل مراجعة المواصفة والسلوك المعتمد.

## 5. المحرر

المطلوب التالي: rename على مستوى المشروع بأمان مع الأسماء المستعارة والأجزاء
والتصدير، وتنظيم الاستيرادات، وquick fixes مرتبطة بتشخيصات حقيقية. حافظ على
إلغاء الطلبات المتقادمة، وعدم تحليل المشروع كاملًا لكل حرف، وتأجيل توثيق Dart
الثقيل كما في العامل الاختياري الحالي. أضف قياس زمن completion/diagnostics
على مشروع صغير وكبير؛ نجاح اختبار وظيفي وحده لا يثبت السرعة.

## 6. F5 والتحديث الفوري والتصحيح

أُضيف مسار مستقل داخل `quds debug` لـFlutter DAP:

1. عند حفظ قدس، تُفحص شجرة الاعتماد قبل الكتابة.
2. بعد `flutter.appStarted` يرسل الوكيل `hotReload` عبر DAP.
3. يحدّث خرائط ملفات قدس بعد نجاح البناء، مع حجب ردود الطلبات الداخلية.
4. أوامر VS Code: **Quds: Hot Reload** و**Quds: Hot Restart** تحفظ الملفات ثم
   تطلب العملية؛ إعادة التشغيل العادية تمر عبر المسار نفسه.
5. خطأ الترجمة يحافظ على الناتج السابق ولا يرسل طلب تحديث. التصحيح والحفظ
   يستأنفان العمل. لا توجد إعادة تشغيل تلقائية تُسقط الحالة بعد رفض reload.

اختبارات بروتوكول بعملية مستقلة تثبت الحفظ، والتسلسل، وإعادة التشغيل، والتعافي،
وتحديث موضع breakpoint بملف مستورد. هذه ليست تجربة على محرك Flutter. يبقى
التحقق على جهاز حقيقي من بقاء state، وstack frames، وقيم المتغيرات بأسماء قدس،
ورفض التغييرات البنيوية. وضعا profile/release و`--no-hot` لا يشغّلان المراقب.
التفاصيل في [FLUTTER_LIVE_UPDATES.md](FLUTTER_LIVE_UPDATES.md).

## 8. CI فعلي عبر المنصات

أُضيفت إعدادات GitHub Actions للفحص الكامل على Ubuntu، ومجموعة محمولة على
Linux/Windows/macOS، واختبار widget وبناء ويب للأكاديمية بمحرك Flutter حقيقي.
تكوين workflow ليس نتيجة نجاح. يجب مراجعة تشغيله بعد الرفع وإصلاح الفشل.
المجموعة المحمولة ليست كامل اختبارات المترجم على Windows وmacOS؛ وسّعها بعد
إزالة افتراضات shell والمسارات من الاختبارات المتبقية.

محليًا لا يتوفر محرك Flutter مكتمل؛ تنزيل artifacts الرسمي كان محجوبًا بـ403
في هذه البيئة. لذلك تظل نتائج أجهزة Flutter الفعلية، وAndroid/iOS/desktop،
اختبارات قبول مستقلة. لا تستبدلها بنتائج peers البروتوكول.

## 9. الاستقرار والإصدار

لا ترفع رقم الإصدار المستقر اعتمادًا على مرور suite فقط. بوابة الإصدار:

## Function-value metadata follow-up — 2026-11-18

Native non-generic function and method values now preserve optional positional
and required/optional named parameters, including nested native callback types.
Structural annotations use the approved parameter grammar, for example
`([value: int = 0]) -> int` and `(value: int required) -> int`.
A default in a function type records optionality; it does not replace the
underlying callable's default. Native defaults execute in Dart when omitted;
explicit null remains explicit null. Function subtyping checks parameter kinds,
labels, omission and contravariance. Reordered calls capture the callable and
arguments exactly once in source order. Earlier optional/named limitations in
this document are superseded for this slice. Generic function values, richer
record signatures and full Quds declaration/lambda parameter-form parity remain
unfinished. Tests: native_function_values.quds (eight declarations), fourteen
negative cases, deterministic Dart golden, actual Dart analysis and VM/JS runs.
