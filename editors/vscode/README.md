# Quds for VS Code

Highlights `.quds` files, formats the open buffer, and shows compiler diagnostics. `#region Title` folds through `#end region`, and the title stays on the collapsed line. Enter on a blank line stays at that column. Enter after a line that ends with `:` indents to the start of the body. Hovering a name or expression shows its type. F12 and Ctrl+click open its declaration in the `.quds` file. Above `main`, Run, Debug, and Profile start the program, stop on a breakpoint in the `.quds` file, and benchmark it.

The extension starts `dart run bin/quds.dart lsp` when the open file is inside this package, walking up from the file when no folder is open. Otherwise it starts `quds lsp`, including `~/.pub-cache/bin/quds` when that directory is not on `PATH`. It looks for `dart` on `PATH` and in the usual Flutter install locations. Set `quds.serverCommand` to replace that, for example `["dart", "run", "/path/to/bin/quds.dart", "lsp"]`.

On Linux, `bash install.sh` from the repository root installs Dart if needed, activates the `quds` command, and installs this extension. You can also install the folder with **Developer: Install Extension from Location**. Then open a `.quds` file and run **Format Document**. **Quds: Restart Language Server** starts the server again.

Formatting uses the same rules as `quds format`: two-space indents, an 80-column wrap after a comma, and comments and string contents left as written. A buffer that does not parse is not formatted. The language server reads the editor buffer, including text that has not been saved. Hover uses that buffer. A mutable binding shows `var name: Type`, a getter/setter shows `property name: Type` (or `get`/`set` when only one side exists), and a function shows `name(parameters) -> Type`. Semantic tokens color those differently: a property or variable is not painted as a function. Another expression shows its type. The three actions above `main` save the file. Run and Profile use a terminal named Quds. Debug builds into `.dart_tool/quds/out/` and stops on breakpoints set in the `.quds` file. The gutter accepts a breakpoint because the Quds debugger is registered for this language. A blank line stays unverified. Stepping and variables come from the Dart VM; local names in the variables pane are the generated names. **Quds: Show Generated Dart** opens the source and the generated file together. Hover reads the analysis already kept for that buffer, so moving the pointer does not compile the file again. A position with no type does not open a tooltip. Completion offers names in scope, members after `.`, named arguments, and snippets for `if`, `for`, and `while`. It reuses that same analysis while the current line is unfinished, and a word from elsewhere in the file is not offered as a suggestion.
