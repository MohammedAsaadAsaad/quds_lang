# تنفيذ augment والتحويلات — اتفاق 2026-11-17

طلب المستخدم اعتماد كلمة واحدة `augment` بدل partial/augment، وتعريف التحويلات
داخل الصنف أو داخل جزء استكماله. هذا امتداد مصرح به من مالك اللغة للمواصفة 1.2؛
تبقى `to` و`to?` و`as` و`is` بمعانيها المعتمدة.

## القواعد المتفق عليها وخطة التنفيذ

1. `augment Type:` يستكمل صنف قدس في المكتبة نفسها، بما فيها ملفات `part`.
   تدمج الحقول والطرق والخواص والمنشئات قبل التحليل؛ لا يغيّر الوراثة أو الهوية.
   العضو المكرر خطأ، وتُفحص المنشئات بعد الدمج. المصدر الأصلي لكل عضو محفوظ.
2. خارج مكتبة النوع، ولأنواع Dart مثل int، الإضافات سلوك وخواص محسوبة وتحويلات.
   لا حقول مخزنة أو منشئات أو تغيير بنية النوع، ولا امتياز للوصول للخصوصية.
   الإضافات الخارجية تصبح مرئية باستيراد مكتبتها، والتعارض لا يحسم بترتيب الاستيراد.
3. داخل الصنف أو augment، `implicit cast(value: Source) -> Target` و
   `explicit cast(value: Source) -> Target` تعريفان على مستوى النوع. أحد طرفي
   التحويل يجب أن يرتبط بالنوع الذي يحتوي التعريف. التعريف الضمني قابل للطلب صراحة.
4. `to` يستدعي التحويل المحدد، و`to?` يعيد null عند ConversionError فقط.
   الأخطاء البرمجية الأخرى لا تُبتلع. يبقى `as` فحص نوع، ولا يستدعي هذه الدوال.
5. الضمني يُوظف في السياقات ذات النوع المتوقع: الربط والإسناد والإرجاع والمعاملات
   والعمليات المدعومة. يبقى `number = 5` من النوع int. لا تحويل عند مجرد فحص علاقة
   الأنواع، ولا سلاسل تحويلات، ولا تحويل داخل const، ولا إسقاط readonly/nullability.
6. التطابق الطبيعي له الأولوية، ثم تحويل ضمني مخصص واحد. المرشحون المتساوون
   الغامضون خطأ. تُقيَّم القيمة والمستقبل والمعاملات مرة واحدة بترتيبها المكتوب.
7. اختبار قدس أساسي لـ int/Fraction وأنواع محلية ومستوردة، ورفض ساكن، وDart
   golden وتحليل وتنفيذ VM/JS، ثم فحص شامل وتوثيق ورفع كل حزمة مكتملة.

تقدم التنفيذ وقيوده الدقيقة ونتائج الاختبار تُسجل هنا عند إغلاق كل حزمة.
هذه الفقرة خطة مصرح بها، وليست ادعاءً بأن البنود منفذة الآن.

## الحزمة الأولى — augment (مكتملة)

دمج الأصناف المحلية وأجزاء part قبل التحليل، وإضافات السلوك الخارجية عبر
الدوال الممتدة المصدرة. حفظت خرائط المصدر مواقع الأعضاء في ملفات part.
اختبارات قدس تغطي الحقول والطرق والأنواع العامة وint والاستيراد، مع رفض
التكرار وتغيير الوراثة والتخزين الخارجي وتخصيص المعاملات العامة.
التحقق: 528 اختبارًا ناجحًا، صفر فشل/تخطي، 5 دقائق و30 ثانية، وتحليل بلا أخطاء.
حدود هذه الحزمة: لا دمج enum/sealedType/extensionType، ولا إضافات static
خارجية عادية؛ لا تدّعي اختبار قيم debugger داخل كل عضو منقول من part.
التحويلات ما زالت الحزمة التالية.

## الحزمة الثانية — التحويلات وتنفيذ الاتفاق

```quds
use quds:math::number show Fraction, fraction

accept(value: Fraction) -> int = value.numerator

main():
  value: Fraction = 7
  print accept(8)
  print (2 + value).numerator
  print value to int
  print fraction(1, 2) to? int
```

المخرجات: 8 ثم 9 ثم 7 ثم null. تعريف التحويلين موجود داخل جسم Fraction
في `lib/sdk/math.quds`، وليس ضمن قواعد خاصة باسم Fraction في المترجم.
التحويل إلى int يقبل الكسر المكافئ لعدد صحيح حتى إن بُني مباشرة دون اختزال،
ويرفض المقام صفر والنتيجة خارج مدى int الخاص بالمنصة. لا يستخدم تقريب double.

### ما نُفذ

- تحليل التعريفات كـ AST، ثم استخراج أجسامها إلى دوال مكتبية مولدة بأسماء ثابتة
  قبل بناء الرموز؛ لا يوجد تحويل نصي بتعابير regex ولا dispatch ديناميكي.
- تعريف داخل class وaugment محلي وخارجي، والعمل مع part وخصوصية المكتبة.
- الربط والإسناد والإرجاع والمعاملات والمنشئات والأنواع العامة ذات الحدود،
  ومعاملات Dart المسماة، والعمليات العددية/المحمّلة المدعومة على طرفي التعبير.
- الأولوية للتطابق الطبيعي، وفحص الغموض والتكرار، وعدم تغيير نوع القيم المستنتجة.
- دعم to وto?، ونوع ConversionError بهوية واحدة بين الملفات المولدة.
  to? يلتقط هذا الاستثناء فقط، وتبقى الأخطاء البرمجية ظاهرة.
- منع السلاسل وconst وإسقاط readonly/nullability. المصدر محفوظ في التشخيص.
- إضافات عامة خارجية مثل augment List<T>، وتفعيل augment المستورد ببادئة.
- إخفاء أسماء الدوال الداخلية من الإكمال والاقتراحات، وإضافة الكلمات الجديدة
  للإكمال والتلوين في VS Code. الأسماء الداخلية مستقرة عند بناء الملف بمسار
  نسبي أو مطلق، والاستيرادات الداخلية تراعي شجرة ملفات CLI المولدة.

### اختبارات يمكن للعميل التالي تشغيلها

```sh
dart run bin/quds.dart test test/conversions.quds
dart run bin/quds.dart test test/conversions_import.quds
dart run bin/quds.dart test test/conversions_external.quds
dart run bin/quds.dart test test/conversions_native.quds
dart run bin/quds.dart test test/conversions_parts.quds
dart run bin/quds.dart test test/conversions_math.quds
dart run bin/quds.dart test test/augment_generic.quds
dart test test/conversions_test.dart test/augment_test.dart --reporter expanded
dart format .

```

الملفات الأولى تختبر الاستعمال بلغة قدس. مشغّل Dart يضيف حالات الرفض الساكن،
وgolden حتميًا، وتشخيص الغموض المستورد بإحداثيات قدس، وبناء CLI حقيقيًا،
وتحليل Dart وتنفيذ VM وJavaScript، بما فيه حدود Fraction على المنصتين.

### الحدود الدقيقة لهذه الحزمة

- القيود البنيوية للحزمة الأولى ما زالت قائمة: لا إضافة تخزين أو منشئ إلى
  نوع خارجي، ولا دمج enum/sealedType/extensionType، ولا أعضاء static خارجية
  عادية. التحويلات عمليات على مستوى النوع ذات مسار مستقل ومدعوم.
- أجسام التحويل تعمل على مستوى النوع دون this؛ عند استعمال عضو static
  من الصنف اكتب Type.member صراحةً في هذه الحزمة.
- الاختيار ضمني في الحدود المذكورة أعلاه، ولا يحوّل حاويات موجودة عنصرًا عنصرًا،
  ولا يجعل List<int> نوعًا فرعيًا من List<Fraction>، ولا يضيف تحويلات للتطابق
  في الأنماط أو لفحص is/as. لا ندّعي تغطية كل أشكال collection literals أو
  variadics أو callback inference أو compound assignment للأعضاء والفهارس.
- في العمليات، يُبحث في التوقيع الطبيعي وفي التحويل إلى نوع الطرف الآخر أو
  النوع العددي المتوقع؛ لا بحث شامل عن نوع ثالث غير موجود بين الطرفين.
- قوائم show/hide تختار التحويلات بحسب نوعها المالك؛ استيراد مكتبة augment
  خارجي كاملة هو المسار المغطى للاستخدامات السلوكية الخارجية.
- وجود مخرجات Dart وJavaScript صحيحة في هذه الاختبارات لا يعني التكافؤ مع
  كل صيغ Dart أو تنفيذ كل ميزات C#، ولا يغيّر سياسة الكسور والأعداد المعتمدة.

نتائج الفحص النهائي مثبتة في VALIDATION.md بعد اكتمال التشغيل على المصدر الثابت.

### إصلاح ظهر في الفحص الشامل

أثناء فحص الحزمة انقطع اتصال VM في آخر مرحلة من أداة قياس الذاكرة. عُزّز
تزامن `tool/profile_heap.dart`: انتظار PauseStart فعلي قبل تشغيل الحمل،
واحتساب كل موضع debugger في الحمل مرة واحدة لعزل أحداث الإيقاف المكررة
وأحداث isolates الأخرى. أضيف اختبار حتمي لهذا التمييز؛ نجحت اختبارات الأداة
الثلاثة، ومنها قياسا VM وNode الحقيقيان. لا يوجد retry يخفي فشل القياس،
وما زالت الأداة تتحقق من أعداد الكائنات والتحرير وذاكرة readonly الضعيفة.

## متابعة تشغيل التحويلات عبر export

أصلح مسار تشغيل/تصحيح مشروع متعدد الملفات يستورد Fraction وتحويله عبر إعادة
تصدير quds:math. تتوحد ملفات SDK داخل خرج المشروع، ويتحقق الكاش من التبعيات
والحزم وخرائط المصدر بدل ضمان ملف الدخول فقط. المثال الأصلي والتبسيط الصحيح
ومعنى explicit عند وجود تحويل SDK ضمني في
[SDK_EXPORT_RUN_DEBUG_AR.md](SDK_EXPORT_RUN_DEBUG_AR.md).
